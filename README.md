## 1. Project Overview

[cite_start]This project is a comprehensive implementation of a **hybrid cryptographic system** designed to secure the electronic exchange of sensitive medical records between hospitals, such as Ridge Hospital and Korle-Bu Teaching Hospital[cite: 14, 69, 70]. [cite_start]It addresses the critical challenges of data confidentiality and secure key management in digital health communication[cite: 13].

[cite_start]The system combines the efficiency of the **Data Encryption Standard (DES)** for encrypting large patient data files with the security of the **Rivest-Shamir-Adleman (RSA)** algorithm for safely exchanging the DES session key[cite: 15, 16, 17]. [cite_start]The entire system is accessible through a modern, user-friendly web-based graphical user interface (GUI) built with React[cite: 31].

## 2. Features

* [cite_start]**Hybrid Encryption Model:** Leverages DES for fast symmetric encryption of large files and RSA for secure asymmetric encryption of the session key[cite: 59, 60, 62].
* [cite_start]**Secure Session Key Exchange:** Uses the RSA algorithm to ensure that only the intended recipient, possessing the corresponding private key, can recover the DES session key[cite: 16, 40].
* [cite_start]**Data Integrity & Authentication:** Incorporates digital signatures created with RSA to provide message authentication and verify that the data has not been tampered with during transit[cite: 32].
* [cite_start]**Real-World Healthcare Scenario:** Demonstrates a practical application for securing electronic medical records, a critical need in modern healthcare[cite: 69, 70].
* [cite_start]**Intuitive Web Interface:** A React-based frontend allows users to easily perform encryption, signing, decryption, and verification operations[cite: 31].

## 3. System Architecture

The system operates on a clear, two-stage process for both encryption and decryption, as depicted in the architecture diagrams below.

### 3.1. [cite_start]Sender's Workflow (Encryption & Signing) [cite: 34]

1.  A unique, random **DES session key** is generated for the transmission.
2.  [cite_start]The patient's medical record is **encrypted using the DES algorithm** and the generated session key[cite: 36].
3.  [cite_start]The DES session key itself is **encrypted using the receiver's RSA public key** to ensure secure delivery[cite: 37].
4.  [cite_start]A **digital signature** is generated by creating a hash of the original record and signing it with the sender's RSA private key[cite: 32].
5.  [cite_start]The encrypted record (ciphertext), the encrypted session key, and the digital signature are packaged together for transmission[cite: 38].

### 3.2. [cite_start]Receiver's Workflow (Decryption & Verification) [cite: 39]

1.  [cite_start]The encrypted **DES session key is decrypted** using the receiver's RSA private key[cite: 40].
2.  [cite_start]The recovered DES session key is used to **decrypt the medical record ciphertext**, restoring the original patient data[cite: 41].
3.  [cite_start]The **digital signature is verified** using the sender's RSA public key to confirm the record's authenticity and integrity[cite: 42].

## 4. Getting Started

This project consists of a Python-based backend for cryptographic operations and a React-based frontend for the user interface.

### Prerequisites

* **Python 3.13**
* **Node.js & npm**

### 4.1. Backend Setup (Python)

1.  Navigate to the project's root directory.
2.  Create and activate a virtual environment (recommended):
    ```bash
    python -m venv venv
    # On Windows:
    venv\Scripts\activate
    # On macOS/Linux:
    source venv/bin/activate
    ```
3.  Install the required Python dependencies, including `pycryptodome`:
    ```bash
    pip install pycryptodome
    ```

### 4.2. Frontend Setup (React)

This project was bootstrapped with [Create React App](https://github.com/facebook/create-react-app).

1.  Navigate to the `frontend` directory:
    ```bash
    cd frontend
    ```
2.  Install the required Node.js dependencies:
    ```bash
    npm install
    ```
